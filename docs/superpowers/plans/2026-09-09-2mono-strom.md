# "2mono" mixer channel — Strom core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a live per-channel `2mono` property to the Strom Audio Mixer so any stereo input channel can be split into two independently-processed mono strips (original L and original R), each with its own gain/fader/dynamics/EQ, both routed centered to the buses — toggleable at runtime **without a Strom restart**.

**Architecture:** Each mixer channel is restructured to *always* run two mono chains (L/R) between the input capsfilter and the existing post-processing (meter/pan/routing/aux/PFL/AFL). A live-selectable router combines the two mono sides either as `interleave(L',R')` (2mono OFF — today's stereo image) or as a centered `sum(L',R')` duplicated to both channels (2mono ON). When 2mono is OFF the L/R parameter sets are linked (identical values); the Open Live UI writes both sides. No elements are added/removed on toggle → no pipeline rebuild → no restart.

**Tech Stack:** Rust, GStreamer (1.26), gst-plugins-rs (`lsp-rs-gate/compressor/equalizer/limiter`), `interleave`/`deinterleave`/`adder`/`audioconvert`/`audiomixer` from gst-plugins-good/base. Strom repo: `strom/`.

**Repo:** `strom/` (worktree/workspace: `/home/nygard/open-live/strom`). Backend + frontend Open Live changes are a SEPARATE plan (Phase 2), written after this plan is executed and the property contract is pinned by real tests.

## Global Constraints

- All code/comments/commits in English. No emojis in log macros. (strom/CLAUDE.md)
- API/types changes require `#[utoipa::path(...)]` + registration in `openapi.rs`, then run `cargo test --test openapi_test` and update `openapi.json` intentionally. (strom/CLAUDE.md)
- Never `clone()` strong refs to pipeline/elements inside signal closures; use `WeakRef`. Do not add per-buffer BUFFER probes. (strom/CLAUDE.md)
- `gst-inspect-1.0` inside the container does NOT show `lsp-rs-*` plugins (they are statically registered in the app, `backend/src/main.rs:415`). **Verify element availability by BEHAVIOR** (build a test flow), never by gst-inspect. (strom/CLAUDE.md + observed)
- Default DSP backend is `rust` (`dsp_backend` default in `definition.rs:48`). `lsp-rs-*` elements must accept **mono** caps — unverified; Task 0 is the spike/gate.
- Existing live property mechanism maps one `ExposedProperty` → one element+property. Multi-element fan-out (linking) is done by the **client** (Open Live controller writes both `_l` and `_r` props). Single-value props `ch{n}_fader`/`ch{n}_gain`/`ch{n}_mute` that previously drove one stereo element are **removed** and replaced by `_l`/`_r` pairs — this is an intentional, documented breaking property-contract change.

- Tests that require a GStreamer element must run in CI; do not rely on tests that silently skip. State which tests ran in the PR body.
- Nothing is committed without explicit user approval; the strom fork is a local dirty repo.
- 44.1 kHz resampling discipline from earlier mediaplayer work is unrelated here but must not regress: the mixer input capsfilter stays `F32LE / 2ch / interleaved`.

### Task 2: Restructure the per-channel build into dual mono + live router

**Files:**
- Modify: `backend/src/blocks/builtin/mixer/builder.rs` (channel loop, currently lines 632-1170)
- Test: `backend/src/blocks/builtin/mixer/tests.rs`

**Interfaces:**
- Consumes: Task 1 helpers; existing `caps_{ch}` element (stereo `capsfilter`, builder.rs:672-686); existing downstream element ids that MUST keep their names: `level_{ch}`, `pre_fader_tee_{ch}`, `pan_{ch}`, `post_fader_tee_{ch}`, `routing_tee_{ch}`, `pfl_volume_{ch}`, `afl_volume_{ch}`, aux/to_main/to_grp elements.
- Produces: per channel the new topology (all ids listed below) plus live router gate ids:
  - `deint_{ch}` (deinterleave, sink from `caps_{ch}`)
  - `fader_l_{ch}` / `fader_r_{ch}` (`volume` elements carrying `fader_l/r` + `mute_l/r` as `volume`/`mute`)
  - `il_{ch}` (interleave: src from `fader_l_{ch}`→pad0, `fader_r_{ch}`→pad1)
  - `sum_{ch}` (adder, mono: sums `fader_l_{ch}` and `fader_r_{ch}`)
  - `up_{ch}` (audioconvert: mono `sum_{ch}` out → stereo duplicate/center)
  - `sel_s_{ch}`, `sel_c_{ch}` (two `volume` gates: 1.0/0.0, toggled live by the 2mono property)
  - `route_{ch}` (adder, stereo: sums gated `il_{ch}` branch and gated `up_{ch}` branch → feeds `level_{ch}`)
  - `is_stopped`-style runtime state is NOT needed here.

**Routing rule:** 2mono OFF → `sel_s=1.0, sel_c=0.0`. 2mono ON → `sel_s=0.0, sel_c=1.0`.

## Behaviour contract (decisions locked with the user)

- 2mono splits a *stereo container carrying two independent mono programs*. Original L (side `_l`) and original R (side `_r`) become independent strips.
- Routing in 2mono: original L → **both** output channels; original R → **both** output channels (centered). This is not "L stays left".
- DSP model: **always dual-mono**. When 2mono is OFF the L/R settings are linked (identical values, written by the client to both `_l`/`_r` props). Gate/comp in stereo mode therefore behave as linked dual-mono, not true stereo-linked — accepted.
- Faders: when 2mono is ON the per-side faders are the only level control (no master). When OFF the single UI fader writes both side faders identically. The Open Live controller performs the copy on toggle so the level does not jump.
- The toggle must be live (no Strom restart). Achieved via fixed-topology router + live gate volumes (Task 4).
- Existing downstream behaviour (meter pre-fader, pan, PFL/AFL, aux pre/post, group/main routing) operates on the **combined** router output and is preserved in id/name. PFL/AFL/aux semantics in 2mono operate on the combined centred signal; document this in Phase 2 UI copy.
- Breaking change: `ch{n}_gain`, `ch{n}_fader`, `ch{n}_mute` are removed; `*_l`/`*_r` replace them. Open Live flow-generator defaults, controller, and audio panel must be updated in Phase 2.
